# Специфікація вимог до програмного забезпечення (SRS)
**Стандарт:** ISO/IEC/IEEE 29148:2018  
**Проєкт:** Програмна система сюжетного психологічного трилера на рушії Unity  
**Автор:** Кирилова Е.Г.  

## 1. System Context
Програмний комплекс охоплює обробку просторових контекстних дій, сценарних переходів, поведінки NPC, інтерфейсу термінала та збереження стану. Взаємодіє з OS Input, Audio API та локальною файловою системою.

## 2. Functional Requirements
* **SRS-FUN-01:** Система повинна здійснювати моніторинг колізійних тригерів у радіусі взаємодії без виклику віконного інвентарю.
* **SRS-FUN-02:** Система повинна автоматично валідувати наявність квестових передумов перед виконанням дії.
* **SRS-FUN-03:** Система повинна здійснювати обхід діалогових графів на базі прапорців сценарію.
* **SRS-FUN-04:** Система повинна транслювати зміну станів квестів через Event Bus.
* **SRS-FUN-05:** Система повинна модифікувати стан NPC за допомогою скінченних автоматів (FSM).
* **SRS-FUN-06:** Система повинна ізолювати логіку віртуального термінала від основного рендерингу.
* **SRS-FUN-07:** Система повинна зберігати стан гри у JSON із геш-сумою SHA-256.

## 3. Non-Functional Requirements
* **SRS-NFR-PERF-01:** Фреймрейт не менше 60 FPS (час кадру <= 16.6 мс).
* **SRS-NFR-PERF-02:** Latency подій в Event Bus <= 5 мс.
* **SRS-NFR-MEM-01:** Виділення пам'яті (GC Alloc) <= 10 КБ на кадр.
* **SRS-NFR-DATA-01:** Час збереження/завантаження <= 50 мс.
* **SRS-NFR-SEC-01:** Перевірка цілісності сейвів алгоритмом SHA-256.
* **SRS-NFR-QUAL-01:** Покриття бізнес-ядра тестами >= 75% (Unity Test Framework).

## 4. Verification Criteria
* Вимоги перевіряються через Unity Test Framework, Unity Profiler та симуляцію пошкодження файлів сейвів.

## 5. Glossary
* **Event Bus:** Шина повідомлень Pub/Sub для зв'язку без прямих посилань.
* **FSM:** Скінченний автомат керування станами.
* **ScriptableObject:** Структура конфігурацій даних у пам'яті Unity.
